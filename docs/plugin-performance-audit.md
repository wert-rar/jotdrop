# Оптимизация производительности плагина

2026-10-17, 15:42 Europe/Moscow. База: b1accedbdde4e3916c0656326a56a5e577e7c048, совпадала с live origin/main при gated-сборке. Изменения реализации находятся в рабочем дереве; установки и публикации не было.

## Что реализовано

- Поиск использует актуальный снимок и сохранённые карточки; debounce 120 мс и окно 60 карточек сохранены.
- Причины обновления разделены на files, metadata, layout, assets и all. Внутренние сохранения передают затронутые пути; сортировка и ширина не перечитывают содержимое.
- Изменения посторонних Markdown-файлов не обновляют доску. Используемые ссылки/встраивания проверяются через metadataCache; при rename учитываются оба пути. События вложений сохраняют обновление представления без чтения текстов.
- Кэш находится в каждом представлении. Новые и изменённые файлы читаются адресно; удаление, переименование и перемещение папки обновляют ключи кэша. Событие metadataCache обновляет свойства без чтения содержимого.
- Неизменившиеся DOM/Markdown-компоненты сохраняются; заменённые освобождаются адресно. Устаревшие чтения не принимаются, неудачные сохраняют инвалидацию, закрытие освобождает кэш.
- Сохранены ручные колонки, сортировка, выбранные карточки, загруженное окно и защита dragstart → dragend. При неудачной записи переноса данные перечитываются для отката оптимистического состояния.
- Удаление frontmatter очищает старые pin/rank даже при отстающем metadataCache.

## Метод и ограничения

Production bundle запускается в headless Edge с настоящими DOM/CSS и синтетическими заметками. Obsidian API подменены; cachedRead читает из памяти, MarkdownRenderer использует markdown-it, YAML fixture представлен JSON. Вызовы cachedRead не равны физическим чтениям с диска.

Регрессия поиска использует настоящий DOM input и debounce. Диагностический probe отдельно измеряет render после установки query, без debounce. В probe обе поисковые строки совпадают со всеми заметками; разные и пустые результаты проверяет регрессия.

Порции загружаются через настоящий callback renderWindow/IntersectionObserver, вызываемый тестом явно. Это воспроизводимое измерение порционной загрузки, не настоящая пользовательская прокрутка. workMs включает ожидание render; для серии оставшихся порций также включает промежуточные animation frames. paintMs дополнительно ждёт два animation frames.

Первое открытие всё ещё читает весь набор последовательно. После загрузки и скрытия всех 1000 карточек остаются 1000 сохранённых DOM и 1000 Markdown-компонентов; закрытие освобождает компоненты и кэш. Heap в байтах и поведение настоящего Obsidian не измерялись. Удержание кэша не объявляется утечкой. Виртуализация и параллельное чтение не внедрялись по выбранным границам.
